# Local wheel app implementation plan

> **For agentic workers:** Execute independent tasks in parallel, test each real interface, and integrate in the existing worktree. Do not commit unless asked.

**Goal:** Ship a usable local wheel management app with real monitoring, settings, profiles and game setup.
**Architecture:** Standard-library HTTP API, static browser app, isolated relay process and serialized MOZA settings client.
**Tech Stack:** Python, evdev, optional pyserial, HTML/CSS/JS.
**Spec:** docs/superpowers/specs/2026-09-18-local-app.md

## Global constraints
- Localhost only by default; validate requests and all device values.
- No unattended motor probes or game launches.
- No edits to the separate Documents/dev/mozaproxy checkout.
- Distinguish saved, applied, unsupported, and unknown values.

## Work
- [x] Backend: mozaproxy/web.py and app_state.py, tests/test_web.py. Implement the exact spec API, passive monitor, safe owned subprocess lifecycle, atomic profile persistence, diagnostics and localhost protection. Test hostile requests, input validation, profile round trip and unavailable hardware.
- [x] Interface: mozaproxy/webui/index.html, app.js, style.css, local fonts. Implement all six routes, real API requests, keyboard access, loading/error/disconnected states, save/apply controls and game launch-option copying. Desktop and narrow layouts.
- [x] Hardware: mozaproxy/hardware.py, tests/test_hardware.py. Inspect installed Boxflat protocol, implement original serial transport and a validated device-setting catalog. Test packet encode/decode, readback, range checks and competing ownership. No automatic writes.
- [x] Debug: inspect raw PID FFB encoding and frozen-run evidence without touching the motor; record bounded next diagnostics.
- [x] Integrate: CLI/install launcher, read-only live check, full automated suite, browser desktop/mobile checks, review and update README/compatibility notes.
