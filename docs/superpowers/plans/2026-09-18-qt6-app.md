# Native Qt6 app implementation plan

User explicitly replaced the web UI requirement with a Qt6 desktop app. This
supersedes the earlier web direction and authorizes implementation now.

Architecture: PySide6 Qt Widgets calls the existing AppState directly. No HTTP
server, browser engine or WebView in the desktop execution path. A single
background executor owns slow operations; queued Qt signals deliver results.
The GUI polls cached snapshots and preserves edits. Reuse existing profile data,
hardware validation, serial ownership and relay lifecycle.

- [x] Add tested Qt controller for async operations and orderly shutdown.
- [x] Build native sidebar/stack with overview, settings tabs, input tables,
  profiles, games and diagnostics. Typed Qt controls, explicit read/apply,
  unchanged settings not submitted; invalid edits block apply and save.
- [x] Add desktop launcher and install integration; make Qt the primary app.
- [x] Test with fake hardware and offscreen Qt, then run a desktop smoke test.
  No unattended motor or configuration writes. Stop the obsolete running web
  server, launch native app and verify visible native window.
- [x] Update product/design/docs to reflect native Linux Qt, record limits.
